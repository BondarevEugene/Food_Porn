# Food_Porn Mini CRM v1.0

Обновление существующего Python-проекта Food_Porn. Устанавливается локально в PyCharm; GitHub и действующая Neon-база из этой поставки не изменяются удалённо.

## Установка в Windows / PowerShell

1. Остановите `launcher.py` и бот сочетанием Ctrl+C.
2. Распакуйте архив. Папку `_crm_update_1_0` положите непосредственно в корень `Food_Porn`, рядом с `launcher.py`.
3. Откройте терминал проекта с активной `.venv` на Python 3.11+; проверено на Python 3.12.
4. Выполните:

```powershell
python .\_crm_update_1_0\apply_update.py --apply
python launcher.py start
```

Установщик добавляет зависимости cryptography, itsdangerous и aiosqlite; остальные версии окружения не обновляет. Сохраняет копии заменяемых файлов и `.env` в `_crm_backup_ДАТА_ВРЕМЯ`. Для существующего сценария Mini App, конфигурации и зависимостей применяет правки с проверкой контекста. При неоднозначной локальной версии остановится до замены файлов и укажет имя файла. Полностью переписываются `main.py`, `app/admin_app.py` и Telegram-обработчик админки — это новые модули данного обновления.

Установщик автоматически создаёт `CRM_ENCRYPTION_KEY` и `ADMIN_SESSION_SECRET`, если они не заданы. Существующий ключ шифрования не меняется. Храните резервную копию `.env`: без исходного ключа сохранённые рекламные токены не расшифровать.

Добавляются только четыре таблицы: `crm_expenses`, `crm_audit`, `crm_integrations`, `crm_customer_notes`. Ревизия и цепочка Alembic не меняются; старые таблицы не удаляются и не перестраиваются. При ошибке установки файлы восстанавливаются автоматически. Новые пустые CRM-таблицы, если успели создаться, остаются в базе.

Проверка pytest выполняется с тестовым BOT_TOKEN, SQLite и тестовым OPENAI_API_KEY; она не обращается к боевому Telegram, OpenAI или Neon. Общая проверка пакета: 141 тест. Для предварительного просмотра списка изменений можно запустить установщик без `--apply`.

## Как открыть

В Telegram: `/start` → **Mini CRM**, либо `/admin` → **Открыть Mini CRM**. Кнопка добавлена в обычное главное меню и в главное меню с включённым Mini App. Публичный HTTPS-адрес берётся из действующего `MINIAPP_URL`; используется тот же домен и маршрут `/crm`.

Список VIP хранится в `app_settings.vip_usernames`. Если записи ещё нет, используется `Settings.default_vip_users` из `app/config.py`. Регистр и начальный `@` не важны. Удаление логина из списка сразу отменяет доступ на следующем запросе. Одного `FREE_GENERATION_TELEGRAM_IDS` недостаточно для доступа к CRM.

VIP-логины теперь дают бесплатную генерацию и доступ к CRM: клиенты, заказы, финансовый учёт, цены и отчёты. Только владельцы из `ADMIN_TELEGRAM_IDS` и владелец веб-админки могут изменять список VIP и рекламные API-ключи. Настройте свой числовой ID в `.env`, если ещё не сделали этого:

```env
ADMIN_TELEGRAM_IDS=ваш_числовой_Telegram_ID
```

Для входа в браузере сначала используйте `/admin/login`, затем пункт **Mini CRM** или `/crm` на том же сервере. При `MINIAPP_PORT=8080` локальный адрес — `http://localhost:8080/crm`. Веб-вход требует вашего `ADMIN_PASSWORD`; стандартного пароля больше нет. Настройки:

```env
ADMIN_USERNAME=ваш_логин
ADMIN_PASSWORD=ваш_сильный_пароль
```

Если `APP_ENV=production`, вход через cookie требует HTTPS. Через Telegram используется проверенная подпись initData на каждом запросе. Гостевая оболочка `/crm` не содержит клиентских или финансовых данных.

## Что работает

- **Обзор:** период 7/30/90/365 дней, UAH и Stars отдельно, коммерческие оплаты, VIP, неоплаченные заказы, воронка и график.
- **Клиенты:** пользователи обоих продуктов, включая покупателей подарков без профиля Customer; поиск по имени, телефону, Telegram ID, внутренние заметки, экспорт CSV для Excel.
- **Заказы:** меню и карты желаний, статусы, провайдер, зафиксированная цена счёта, фильтры продукта и оплаты, поиск и экспорт.
- **Финансы:** учёт расходов по категориям в UAH/USD/EUR, защита от дублей при повторном сохранении, аннулирование с обязательной причиной. Отдельный просмотр имеющегося ledger; отсутствие его таблиц показывается явно.
- **Реклама:** Meta Ads и Google Ads — аккаунты, версии API, зашифрованные токены, проверка подключения и загрузка отчёта по кампаниям. Расходы, показы, клики, конверсии и период отчёта. Статус «Подключено» появляется только после успешного ответа API.
- **Настройки:** цены новых счетов меню/подарков в Stars, цена меню UAH, курс USD/UAH, базовые цены традиционного сценария подарка. Значения сохраняются в базе, применяются в текущем процессе и загружаются после перезапуска.
- **Журнал:** автор изменений, время и операции; рекламные секреты в него не попадают.

Все семь разделов проверены в браузере на ширинах 1440 и 390 px; проверен веб-вход, сохранение расхода и авторизация через Telegram initData. Изображение `preview.png` показывает интерфейс на тестовых данных.

## Границы финансового учёта

Период отчёта определяется по дате создания заказа: у существующих моделей нет отдельного `paid_at`. VIP-заказы не считаются выручкой. Оплаченные заказы с неизвестным провайдером выделяются и не включаются в денежную выручку. Stars не пересчитываются в гривну. Ledger-пополнения не прибавляются повторно к выручке заказов.

«Учётный результат UAH» — подтверждённая денежная выручка заказов периода минус внесённые расходы UAH. Это не банковский остаток и не чистая прибыль. Комиссии, печать, рекламные и API-расходы нужно внести в журнал. Расходы других валют показаны отдельно.

Аннулирование расхода — учётная корректировка; оно не выполняет возврат через эквайринг. Статусы оплаты заказов нельзя вручную переключить из CRM: используются действующие проверенные платёжные обработчики. В модели ledger валюта не зафиксирована, поэтому его остатки отображаются в минимальных единицах без самовольного назначения валюты.

Новые бесплатные карты желаний Mini App сохраняются как нулевые VIP-заказы в базе. Старые бесплатные карты, которые ранее существовали только в `storage/miniapp_jobs`, автоматически не импортируются и не появляются в статистике базы. Старые файлы и ссылки на подарки остаются рабочими.

## Подключение рекламы

Владельцу: **Реклама** → заполнить аккаунт и API-поля → **Сохранить** → **Проверить и синхронизировать**.

Meta: Ad Account ID (с `act_` или без), поддерживаемая версия Graph API, Access Token с доступом к рекламному аккаунту. Pixel ID сохраняется как настройка; автоматическая отправка событий Pixel/CAPI в это обновление не входит. Поля и отчёты: [Meta Marketing API Insights](https://developers.facebook.com/docs/marketing-api/insights/).

Google Ads: Customer ID, при необходимости Manager ID, OAuth Client ID, Client Secret и Refresh Token. Версия по умолчанию `v25`; API-версия редактируется. Developer Token можно указать для совместимости с конфигурацией аккаунта/версией; код не требует его для сохранения интеграции. Документация: [OAuth](https://developers.google.com/google-ads/api/docs/oauth/single-user-authentication), [Search / SearchStream](https://developers.google.com/google-ads/api/rest/common/search).

Пустое поле токена при последующем сохранении сохраняет прежнее значение. Если ключ шифрования изменился или потерян, CRM покажет ошибку, а не заменит его новым автоматически.

Подключение боевых рекламных аккаунтов требует ваших ключей и разрешений. Контракты адаптеров проверены на имитациях API: пагинация Meta, разделение валют, отсутствие двойного подсчёта Meta-покупок, перевод Google costMicros, обработка отказов и отсутствие секретов в ответах. Реальные рекламные аккаунты в этой поставке не подключались. Создание кампаний, изменение бюджетов, автоматическое расходование рекламных денег и отправка рассылок не выполняются. Метрики конверсий рекламной платформы не подменяют оплаты заказов Food_Porn; сквозная атрибуция ещё не реализована.

python -m pytest -q
