# Mini CRM: подключения хранилищ нескольких ботов

Раздел **Хранилище** поддерживает read-only инвентаризацию S3-совместимых
бакетов по ботам. Существующие подключения Little Legend продолжают
использовать прежние Railway переменные.

## Добавление подключения

1. Создайте в Railway переменные `ENDPOINT_URL`, `BUCKET_NAME`,
   `REGION_NAME`, `ACCESS_KEY`, `SECRET_KEY` (имена произвольные).
2. Создайте `CRM_STORAGE_CONNECTIONS_JSON` со значением:

```json
[
  {
    "bot_id": "food_porn",
    "name": "assets",
    "prefix": "food-porn/",
    "endpoint_env": "ENDPOINT_URL",
    "bucket_env": "BUCKET_NAME",
    "region_env": "REGION_NAME",
    "access_env": "ACCESS_KEY",
    "secret_env": "SECRET_KEY"
  }
]
```

3. Перезапустите сервис. В разделе «Хранилище» появится вкладка Food Porn.

**Безопасность:** в JSON только *имена* переменных окружения. Не помещайте
туда реальные секреты. Если несколько ботов используют один бакет,
их префиксы должны быть непересекающимися. Права доступа S3 желательно
ограничить префиксом бота на стороне провайдера.

## Текущие ограничения

- Реестр задаётся конфигурацией Railway, не редактируется из Mini CRM.
- Списки заказов пока связаны с Neon только для Little Legend.
- Другие боты получают статистику объектов и подключения, но не
  атрибуцию объектов к заказам.
- Удаление облачных файлов **заблокировано** сервером (HTTP 423).
- API R2 не возвращает физическую ёмкость бакета.
- Суммарный объём не считается достоверным при ошибке хотя бы одного
  подключения или при частичной инвентаризации.
