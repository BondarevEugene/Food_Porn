# Little Legend — Retention Control v4

## Neon PostgreSQL: журнал операций

Миграция: `alembic upgrade head` (revision `20261120_0027`).
Создаётся таблица `little_legend_retention_runs` с агрегированными
метриками: время проверки, режим dry-run/execute, статус, коды ошибок,
количество просроченных, задержанных, исчерпавших повторы, физически
удалённых и неудачных удалений; факт отправки уведомления.

**Никаких** имён, идентификаторов детей, ID заказов, object keys, фотографий,
текстов ошибок или содержимого сказок в таблице нет. Сохранение работает
только после успешного выполнения операторской команды и после применения
миграции. Для просмотра из защищённой административной части предусмотрена
функция `recent_retention_runs(session, limit=20)` с ограничением 100 строк.

### Операционные требования

1. Применить миграцию Neon до запуска новой версии CLI.
2. Разрешить чтение журнала **только** авторизованному владельцу/администратору.
3. Ограничить срок хранения агрегированных журналов внутренней политикой.
4. Не публиковать функцию истории через публичный endpoint.
5. Согласовать IAM, bucket versioning и monitoring до подключения cron.

### Границы релиза

Этот PR создаёт долговечный журнал и API чтения для будущего
авторизованного экрана мини-CRM. Сам экран мини-CRM, автоматическая
дедупликация уведомлений и расписание **пока не реализованы**.
Фотографии детей не принимаются и не обрабатываются.
