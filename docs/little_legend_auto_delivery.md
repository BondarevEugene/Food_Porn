# Little Legend — автоматическая доставка PDF

Этот worker обрабатывает **только явно разрешённые владельцем** доставки.
Данные согласия на доставку и состояния хранятся в уже существующей таблице
`little_legend_production_effects` (Neon PostgreSQL). Новая миграция не нужна.

## Запуск на Railway

Создайте **отдельный worker service** из того же GitHub-репозитория и commit,
что и основной Food_Porn. Установите тот же `DATABASE_URL`, `BOT_TOKEN`,
и переменные приватного хранилища изображений Little Legend, которые
использует рабочий сервис. Команда запуска:

```sh
python -m app.little_legend.auto_delivery_worker
```

Не запускайте этот бесконечный цикл в FastAPI lifespan, в каждом web replica
или в нескольких несогласованных cron-задачах.

## Контракт

1. Владелец книги в Telegram Studio нажимает «Отправить книгу автоматически,
   когда будет готова». API сохраняет неизменяемое opt-in задание.
2. Worker каждые 15 секунд проверяет ожидающие заявки.
3. Пока нет рукописи или полного согласованного набора изображений,
   задание остаётся в состоянии `reserved`.
4. После готовности worker собирает PDF из приватного хранилища и использует
   общий `TELEGRAM_PDF` ledger. Telegram отправка фиксируется как
   `dispatched` **до** сетевого вызова.
5. Успешный ответ Telegram подтверждает доставку. При неопределённом исходе
   повторная отправка запрещена до ручной сверки.

**Важно:** владелец должен предварительно начать диалог с ботом.
`owner_id` — это Telegram ID авторизованного пользователя; если бот
заблокирован, отправка не состоится. Отдельная доставка третьему лицу
не поддерживается.

## Операционный контроль

`little_legend_production_effects` с `kind=telegram_auto_request`:
- `reserved`: ожидание готовности PDF
- `confirmed`: Telegram подтвердил отправку
- `uncertain`: проверить Telegram и логи вручную

Таблица с `kind=telegram_pdf` хранит собственный idempotency fence.
Никогда не переводите `uncertain` в `reserved` автоматически.
