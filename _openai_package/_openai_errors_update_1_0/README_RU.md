# Food_Porn — понятная обработка ошибок OpenAI, v1.0

Дополнение к установленной Mini CRM 1.0.1 (или 1.0 с исправлением Windows). Обновляет Python-обработку меню и подарков, добавляет продолжение заказа в Mini App. Пароли, ключи, цены, модели и данные Neon сохраняются.

## Логин и пароль админки

В корневом `.env`, рядом с `launcher.py`, найдите или добавьте:

```env
ADMIN_USERNAME=admin
ADMIN_PASSWORD="ЗАМЕНИТЕ_НА_СВОЙ_ДЛИННЫЙ_ПАРОЛЬ"
```

Уже существующие строки измените, не дублируйте. Пример пароля выше — обозначение для замены. Если логин пуст, используется `admin`; пароль обязательно должен быть задан. `ADMIN_SESSION_SECRET` оставьте тот, который создал установщик Mini CRM.

После изменения `.env` перезапустите бот. В присланном логе сервер использовал `MINIAPP_PORT=8081`:

- вход: http://127.0.0.1:8081/admin/login;
- CRM после входа: http://127.0.0.1:8081/crm.

Для Telegram используется проверенная подпись Telegram и ваш список VIP/ADMIN_TELEGRAM_IDS; веб-пароль не нужен.

## Установка в PyCharm / Windows

1. Остановите бот Ctrl+C.
2. Распакуйте `_openai_errors_update_1_0` непосредственно в корень Food_Porn, рядом с `launcher.py`.
3. В терминале проекта с активной `.venv` выполните:

```powershell
python .\_openai_errors_update_1_0\install.py --apply
```

4. После `OpenAI error-handling update installed`:

```powershell
python launcher.py start
```

Установщик проверяет контекст каждой текстовой правки до замены файлов, создаёт `_openai_backup_ДАТА_ВРЕМЯ`, компилирует код и запускает весь pytest. При ошибке восстанавливает исходные файлы. Изменений схемы базы и новых зависимостей нет. Повторная установка уже применённого обновления ничего не меняет. Предварительный просмотр: запустите `install.py` без `--apply`.

## Логика отказов

| Причина | Что происходит | Что делать |
| --- | --- | --- |
| Нулевые API-кредиты | Остановка после первого отказа, готовые этапы сохранены | Владельцу пополнить баланс OpenAI |
| Лимит проекта/организации | Отдельный код причины; без бесконечных повторов | Проверить соответствующий лимит |
| Ошибка API-ключа (401) | Без повторных запросов с тем же ключом во время паузы | Проверить ключ и принадлежность проекту |
| Нет доступа / неверная модель (403/404) | Текущая генерация остановлена | Проверить разрешения, модель и параметры |
| Временный rate limit (429) | Ограниченные попытки, учитывается Retry-After | Подождать указанную паузу |
| Временная ошибка сервера (5xx) | Ограниченные попытки с растущей задержкой | Продолжить позже, если сервис ещё недоступен |
| Таймаут/обрыв соединения при запросе изображения | Нет автоматического повторного платного запроса | При ручном продолжении учитывайте, что ответ первого запроса мог потеряться |
| Таймаут текстового запроса | Ограниченные повторные попытки | Продолжить позже при повторном отказе |
| Неполный ответ или ошибка сохранения | Отдельная причина; неполный комплект не выдаётся | Проверить журнал/хранилище, продолжить после исправления |
| Отказ проверки изображения | Существующий сценарий смены фото/целей | Сменить данные; бесконечного автоматического обхода проверки нет |

Код, HTTP-статус, request_id и действие для владельца попадают в журнал; сырое тело ответа OpenAI, ключи, фото и промпты в новые сообщения об ошибках не включаются. Пользователь получает объяснение на UA/RU/EN с нужным следующим действием, вместо общего «всё упало». Ошибки API сохраняются в меню безопасным диагностическим префиксом; старые сырые ошибки не выдаются клиенту через API статуса меню.

## Повторы и паузы

- SDK-клиенты создаются с `max_retries=0`: повторами управляет один общий обработчик.
- `IMAGE_RETRIES` — общее число попыток одного запроса, от 1 до 4; по умолчанию 2.
- `Retry-After` поддерживает секунды, дату HTTP и миллисекунды. Если сервер требует больше 30 секунд ожидания, заказ возвращает понятную ошибку с паузой; ранний автоматический запрос не выполняется.
- Отказ по квоте или ключу приостанавливает новые OpenAI-запросы с этим ключом для всех продуктов текущего процесса. Действующие параллельные запросы, уже отправленные до отказа, нельзя отменить с гарантией отсутствия расходов.
- `OPENAI_QUOTA_COOLDOWN_SECONDS=300` — пауза до следующей проверки. После паузы разрешается один проверочный запрос из следующей попытки пользователя. Фоновая платная проверка сама не запускается. Успех снимает блокировку, повторный отказ продлевает её.
- После исправления баланса/ключа можно дождаться этой паузы или перезапустить бот. Новый ключ рассматривается отдельно. Состояние блокировок хранится в памяти одного процесса; для нескольких независимых экземпляров бота оно не общее.

## Продолжение заказа

**Меню:** история заказов в Telegram → открыть неудавшийся сет → «Продолжить создание». В Mini App — открыть заказ и нажать «Продолжить создание». Готовые фотографии блюд повторно не генерируются; запрашиваются только отсутствующие. Повторное нажатие не запускает второй воркер того же заказа. Чужой заказ возобновить нельзя.

**Подарок в Telegram:** после сообщения об ошибке фото, цели, план и завершённые этапы остаются сохранёнными. После исправления причины отправьте те же цели, чтобы продолжить. После перезапуска FSM находится в памяти и теряется: используйте `/resume`; фото сохраняются, но план из FSM может потребовать повторного запроса.

**Подарок в Mini App:** при известном сбое OpenAI фото сохраняются; появляется кнопка продолжения того же задания. План хранится в JSON задания и повторно не запрашивается; завершённые этапы изображения читаются из существующих контрольных файлов. Ввод/файлы удаляются после успешной подготовки результата. Старые задания, чьи фото ранее удалены, требуют создания нового подарка.

При корректной остановке бота активное меню отмечается как прерванное с возможностью продолжения. При жёстком завершении процесса это уведомление может не успеть записаться. Повтор запроса изображения после потерянного ответа не может гарантировать отсутствие повторного списания у провайдера; поэтому он выполняется только по явному продолжению, а не автоматически.

Генерация до выставления счёта сохраняет действующий сценарий проекта. За незавершённое новое меню счёт не создаётся; уже существующие оплаты не отменяются автоматически.

## Проверки

184 теста проходят, включая 43 новых проверки. Проверены настоящие исключения OpenAI SDK и HTTP через MockTransport: один HTTP-запрос при квоте, разные коды лимитов, без утечки исходного тела ошибки, Retry-After, предел повторов, отсутствие автоматического дубля при таймауте изображения, одна проверка после паузы, сохранение данных, продолжение своего заказа, защита от двойного запуска и освобождение очереди после ошибок. Изменён один тестовый объект Mini CRM: добавлена реальная форма поля ai_cost_usd для сохранения плана.

Все проверки используют тестовые ключи, SQLite и имитации ответов. Боевые Telegram, OpenAI и Neon в тестах не вызываются. Подключение OpenAI восстановится после устранения реальной причины в аккаунте; код не изменяет API-баланс и лимиты.

Основные официальные источники: [коды ошибок OpenAI](https://developers.openai.com/api/docs/guides/error-codes), [ограничения и повторные запросы](https://developers.openai.com/api/docs/guides/rate-limits).
